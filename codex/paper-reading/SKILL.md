# Paper Reading

帮助学习者把“问题与约束 → 主张 → 机制 → 证据 → 局限”连成可检验的解释。默认中文正文、首次专业术语附英文；领域惯用英文或中文翻译易失真的词优先保留英文，首次补充中文解释，具体见笔记风格规则。根据实际学习目标调整深度，不把目录翻译当作精读。

## Route and Load

从请求与已有状态选择模式，不要求用户每次重新选择：

- **guided-reading**：交互精读；按理解依赖推进一个自然问题或推导，笔记随教学增长。
- **notes-only**：用户要求一次性整理时，完成所请求范围的笔记；不虚构教学或掌握验证。
- **focused-question**：只读并解释问题涉及的论文部分及必要依赖，不自动创建整篇课程或文件。
- **note-review**：逐项核查指定笔记与来源；用户只要求评估时先报告发现，用户要求修正时更新受影响内容。
- **mastery-review**：用独立回忆、比较或迁移检查已有知识，避免重复整堂讲解。

开始或恢复有文件的学习时，读取 [记录、模板与恢复](references/state-and-notes.md)，再读取该论文进度、路线图和当前单元；长笔记按标题定位。任何实质性论文解读或笔记核查，在本次会话首次使用时读取 [来源与证据](references/source-and-evidence.md)。仅查询出处或维护 skill 时读取 [出处](references/provenance.md)，无需加载整套教学资料。

用户指定位置优先；已有论文库沿用其目录。此用户未指定位置且可确认论文位于 `/Users/nyvo/paper/` 时，使用该库的 `notes/<论文标识>/`。其他环境从实际论文位置和工作区确定目录，不依赖此绝对路径才能工作。

显式调用 `$paper-reading` 可作为采用本 skill 的指令。若仅自动匹配到 skill，而现有进度明确采用另一个协议，沿用该协议，不悄悄迁移。采用本 skill 后在当前进度记录 `paper-reading / 1.0.0 (derived from protocol 2.0)`；保留旧正文和 ID，不批量重写。

## Source and Coverage Contract

- 固定论文标题、版本、文件及页数；PDF 页码从 1 开始，与印刷页码区分。输入抽取截断不算读完。
- 新论文先浏览正文与附录结构、全部 Figure/Table、关键公式位置和结论；在进度建立按原文顺序的 `Source Map and Coverage`，标页码、论证作用、阅读状态和教学去向。再按理解依赖规划 Objective；调换原文顺序须保留回访点。短论文可一次读完，长论文可逐节细化。
- 每个单元开讲前，对照原文细化当前范围的关键定义/变量、公式/命题、论证转折、示例、Figure/Table、实验条件及相关图注、脚注、附录，写出作用与落点；不能用一行章节标题代替。使用前核实会影响当前推理的附录、脚注和限定。浏览、精读、未读分别记录。
- 核心主张所依赖的定义、公式、图表和证据在约定范围内必须讲清或写清；agent 不能自行用“简述/跳过”处理。材料缺失则标未解决，用户明确缩小范围则记录范围变化。
- 核心公式、数值、比较条件、模型变体及结论边界给可定位来源。区分作者主张、报告证据、AI 解释或推论、未解决问题。代码和论文冲突时保留版本与差异。
- 解读图表时同时核对完整任务空间与图中展示的子集，明确类别总数、候选集合、数据划分、基线数量和消融组件是否有省略；未绘制项目不能默认不存在。
- 依赖视觉结构、关键公式或抽取含糊的内容应查看原页面；逐张安排 Figure/Table 的教学位置。依赖图的提问先展示原图或清晰裁剪并解释图注、主要对比和边界；不讲的图记理由或回访点。不能凭模型记忆补原文细节。细节见 [来源与证据](references/source-and-evidence.md)。

## Adaptive Teaching

`guided-reading` 与 `mastery-review` 同时读取并使用可用的 `learn-anything` skill，负责对话节奏、检索题型和提示撤除；本 skill 负责原文核对、来源归属、笔记和进度。其他模式不强制载入。组合使用时，以下规则明确取代其“每次提问必用工具”和“单次会话完成整段 teach-back”的要求：

1. 校准、导航和提示选择可用选择题工具；检索、解释和迁移采用自由文本，可直接在对话中回答，不强制工具，选项不得泄露答案。已有进度足够时不重复校准，不机械要求每段一问。
2. teach-back 按 Objective 收口，可跨会话完成；已有无关键提示的解释与迁移证据可复用，避免重复考核。全文结束仍检查跨 Objective 的完整论证。跨会话间隔回忆记录在进度的 `Open Issues and Review`。
3. 讲解和判定以核实过的原文为依据。用户要答案、跳过或暂停时遵从；参考答案注明依据。刚听完后的复述、“继续”和教师答案均不等于独立掌握。教学内容仍按下文流程先保存再发送。

若 `learn-anything` 不可用，说明后按“必要示例 → 自由作答 → 按缺口补提示 → 独立应用”继续，不阻塞精读。

收到“继续”“接着学”或等价恢复请求时，先读取当前论文的 `进度.md`、正式笔记路线图与 `Source Map and Coverage`（旧笔记可为 `Source Coverage`），以实际文件内容修复冲突；根据覆盖表只选择一个唯一下一单元，先补全其原文项目清单并核对依赖。任何项目尚未归类为“已教学”“明确后置”或“简述/跳过并记录理由”时，先补齐或明确后置，不得用“继续”推断已经掌握，也不得凭上一轮对话记忆直接跳到后续单元。

不机械要求每段一问。正式笔记以连贯解释为主体，问答服务于检验；每篇一份正式笔记，不保存学习者原话、评分或逐轮聊天记录。进度只保存掌握依据和缺口的短摘要。

维护 Obsidian 笔记时，问题保持展开；已揭示的参考答案使用 `> [!answer]- 参考答案` 默认折叠。折叠只辅助先独立回忆，不能替代未答新题不写答案的规则。

离开当前 Section 或转入后续 Figure/Table 前，重新扫原文段落、公式编号、图表/图注、脚注及附录引用，与进度表逐项对账并补清单遗漏。交互模式每项须标“已教学”“明确后置（目标与回访点）”或“简述/跳过并记录理由”；`notes-only` 可标“仅笔记已写”。核心项目不得自行简述/跳过；仍有未归类项目时，不得把该 Section 或对应 Objective 标为已覆盖，也不得推进到依赖它的后续单元。“已查看”只表示来源状态，不表示已经教学。

已到达 Section 的同一张进度表保留简短的“原文项目 → 论证作用 → 笔记落点 → 处理状态”；交互模式已写入但未展示标“待展示”，不能标“已教学”。`notes-only` 的“仅笔记已写”可计入内容覆盖，不能当作教学或掌握。恢复时先处理无落点和状态冲突，再推进；不为同一状态另建重复表。

## Save Once, Then Respond

对于正在维护笔记的模式，每条含新讲解、纠错、参考答案或状态变化的回复发送前执行一次：

1. 对照已有文件确定增量，避免重复追加。
2. 将准备发送的已核实讲解、必要附件及决定揭示的参考答案写入正式笔记；待答的新题暂不写答案。
3. 重读新增内容及相邻上下文，核对变化的论文事实与可定位原文。同版本、可定位的摘录可复用；有视觉或抽取歧义时看原页面。纯格式、日期或状态变化不重读无关 PDF。
4. 检查概念依赖、证据强度、ID、公式、链接和图注，修正受影响内容。
5. 笔记成功保存后再更新进度的保存边界、待答问题、掌握状态和下一动作，确认一致后发送回复。

纯导航和状态查询没有变化时不写文件。一次性局部回答没有笔记维护要求时只核实并回答。来源复核不宣称为独立评审；未核实点如实保留。

写入失败时说明未保存范围并保留最小恢复摘要；不能报告成功。恢复时先根据实际笔记修复落后的进度，再继续。已保存但是否已展示无法确认的单元，不视为已掌握。

## Completion and Blockers

分别报告 **内容完成** 与 **掌握验证完成**。前者要求约定范围覆盖、关键来源可追溯、没有阻断核心结论的未解决事项；后者要求无关键提示的完整论证及合适的迁移、比较或反例证据，覆盖机制和实验证据边界，不能只凭一道局部题。

材料缺失时定位缺少的页、附录或定义，尝试可用的同版本原始来源，仍不可得则记录影响，暂停依赖该信息的判断，继续不受影响的部分。PDF 版本变化时重定位受影响来源；纠正核心解释后，受错误前提影响的掌握项改为待巩固。

暂停前保存下一步具体动作及所需来源；延迟回忆可安排在下次会话或建议日期，仅记录待复习事项不等于创建自动提醒。没有独立回答数据时可结束为“内容完成，掌握待验证”。
