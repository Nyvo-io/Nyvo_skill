# 记录、模板与恢复

用于开始、恢复或维护论文笔记；单次不落盘的问题不需要套用此模板。

## 文件职责

沿用已有文件；新论文默认结构：

```text
notes/<论文标识>/
  学习笔记.md
  进度.md
  attachments/
```

正式笔记保存教师侧耐久知识，进度保存轻量状态与来源索引，不重复正文。索引确实变长时可拆到 `来源索引.md` 并从进度链接，否则不增加文件。

同一论文库的共享学习协议放在 `notes/` 根目录；单篇进度链接协议并记录版本、范围及必要的个别约定，只写差异，不复制整份协议。

初次交互精读只创建 `Paper Information`、简要论证地图、`Learning Objectives` 和 `Learning Roadmap`；正文随教学增长。notes-only 可一次完成所请求内容，内容覆盖不表示学习者已读或掌握。

## 进度模板

用实际值替换方括号示例；没有待答问题或未解决事项时写“无”，不保留伪占位条目。

```markdown
# Progress

- Protocol: paper-reading / 1.0.0 (derived from protocol 2.0)
- Paper: [路径、标题、版本或日期、页数；必要时文件哈希]
- Mode: [guided-reading / notes-only / mastery-review]
- Scope: [约定范围与学习目标]
- Current: [Objective / Q&A ID、原文位置]
- Stop Reason: [等回答、时间暂停、先修缺口或材料阻塞]
- Saved Through: [实际保存的最后单元]
- Pending Question: [问题；准备发送、已发出或展示待确认]
- Next Action: [具体动作与所需来源]
- Content Status: [in-progress / complete-in-scope]
- Mastery Status: [unverified / partial / verified-in-scope]

## Objectives

| ID | 能力目标与依赖 | 来源 | 内容状态 | 掌握状态与依据摘要 |
|---|---|---|---|---|
| O1 | [能解释、比较、推导或判断什么] | [小节、图表、页码] | 待学 | 待验证 |

## Source Map and Coverage

| 原文顺序与项目（PDF 页） | 论证作用 / 依赖 | Agent 阅读状态 | 笔记落点与处理状态 |
|---|---|---|---|
| [当前小节内定义/公式/例子；Figure/Table 单列；相关附录] | [支撑哪一步、依赖什么] | 未读 / 浏览 / 已精读 | 待安排 / 待展示 / 已教学（O…/Q&A…） / 仅笔记已写（notes-only） / 后置至 O… / 简述或跳过及理由 |

## Critical Definitions

| 术语或条件 | 最小定义与关键区别 | 正式来源 | 首次教学位置 |
|---|---|---|---|
| [影响推理的项目] | [含义与作用] | [正文、图注、脚注或附录及页码] | [Q&A ID 或待讲] |

## Open Issues and Review

- [未核实点、影响、下一核实动作]
- [薄弱目标、待复习问题、下次会话或建议日期]
```

每个 Objective 的内容状态：待学、进行中、已覆盖。掌握状态：待验证、提示下完成、独立验证通过、待巩固。依据可记日期、检查类型及短缺口摘要，不记录学习者原话、评分和详细教学流水。

首次通览时按原文顺序登记全部实质小节与 Figure/Table，及可识别的关键定义、公式/命题、示例和相关附录；当前单元教学或写作前再按段落、编号与图注补细，不凭浏览状态标已教学。核心主张依赖的项目不能由 agent 自行简述/跳过；缺材料标未解决，用户缩小范围则记范围变化。此表同时承担来源地图和覆盖核对，不另建重复的 `Coverage Gate`。旧论文可沿用 `Source Coverage`，在继续学习的当前范围逐步补细，不批量迁移。

Objective/Q&A 初始顺序分配 ID，后续保持稳定；学习顺序由路线图表达。插入目标用新 ID，无需重编号整篇。进度是下一动作的唯一状态来源；笔记保留 `Up Next` 时只做一致的短导航。

## 笔记风格

- 正文中文，专业术语首次出现带英文。使用 `Objective N`、`Q&A N`，按需加 `Focus`、`Check Your Understanding`、`Answer` 和 `Hint`；不用每题填全套标签。
- 讲解与笔记均遵循：专业术语及领域常见英语词汇，若领域内惯用英文，或中文翻译容易失真、歧义较大，优先保留原文英文，首次出现补充简明中文解释；有清晰通行译法的术语使用“中文（English）”。后续用词保持一致，必要时允许中英混写，便于对照论文；普通叙述词不刻意英文化，也不以英文替代概念解释。
- 连贯说明承担机制与论证，Q&A 补充检查和易错点；同一背景不重复抄写。
- 参考答案与问题同处一个单元。新题未答时不预先将答案写入可见笔记；复习已有题时明确要求先不看答案。
- Obsidian 笔记的问题保持展开；已提供的参考答案用 `> [!answer]- 参考答案` 默认折叠，答案中的段落、公式、列表和空行都放入同一引用块。折叠只辅助复习，不能替代新题答案暂不写入及先独立回忆的要求。
- 行内公式 `$...$`，独立公式使用单独成行的 `$$...$$`；检查定界符、矩阵、cases 和符号定义。
- 使用当前 vault 可解析的 wikilink 或相对附件路径，外部来源用 Markdown 链接。保留原图号、PDF 页码和用途，验证文件存在与显示清晰。

## 恢复与异常

1. 读取所选协议或 skill、进度、路线图、当前单元及相邻上下文，核对当前原文和版本。
2. 有待答问题先处理；用户只说“继续”可以推进，但不能当作作答证据。
3. 记录冲突时查实际笔记、可见对话和原文；缺乏历史作答证据的状态保持待验证。
4. 已保存笔记但进度滞后，先修复进度；不要重复追加。已保存但回复未发送或展示不明，标明展示待确认。
5. 材料缺失只阻塞依赖该材料的结论。明确缺失点及下一步，避免无限搜引用网络。
6. 版本变化或核心解释被纠正，复核受影响的来源、下游笔记与掌握依据。

采用本 skill 时沿用原正文。旧“完成”有独立表现依据则保留；仅有覆盖或教师答案依据的，记录内容已覆盖、掌握待验证。不要更改旧协议文件，也不要因创建或安装 skill 自动迁移任何论文。

## 结束时的检查

离开单元前，重新对照原文的段落、公式、图表/图注、脚注和附录引用，补上表中漏项，并确认每项落点及处理状态；`notes-only` 的“仅笔记已写”不表示教学或掌握。内容完成前，正文与附录每个实质性小节和全部 Figure/Table 都有去向，待学和后续项目没有悬空，删减范围有理由。掌握验证结合各核心目标表现及整合解释，而不是对笔记质量进行自评分。

在下一会话或合适间隔安排一次不看答案的回忆，按表现调整。固定几天不是普遍最优间隔，保留“当前验证通过”和“延迟保持尚待观察”的区别。
